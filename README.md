# HelpDesk

HelpDesk is a full-stack customer support and ticket management app. Customers submit and track requests, agents work support queues, and administrators manage the team and support operations.

## Stack

- React, Vite, Tailwind CSS, React Router, Axios, React Hook Form, Zod, Lucide, and Recharts
- Node.js, Express, Mongoose, and MongoDB
- HTTP-only JWT cookies, CSRF checks, bcrypt password hashing, Helmet, CORS, and rate limits

## Requirements

- Node.js 20 or newer
- A MongoDB Atlas cluster or a local MongoDB instance

## First run

1. Copy `.env.example` to `.env` and set `MONGODB_URI` and a random `JWT_SECRET` of at least 32 characters. Set `CLIENT_URL` to `http://localhost:5173` for local development.
2. Set `ADMIN_NAME`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD` in `.env` if you want the seed script to create the first administrator. Use a unique password.
3. Install dependencies with `npm install`.
4. Seed the starter ticket categories and optional administrator with `npm run seed`.
5. Start the API and frontend with `npm run dev`.
6. Open the Vite URL, usually `http://localhost:5173`.

The development server proxies `/api` requests to Express on port 5000. To run each process separately, use `npm run dev:server` and `npm run dev:client`. Production frontend assets are generated by `npm run build`; the API starts with `npm start` after its environment is configured.

## Roles and access

- **Customer:** can register, create and follow their own tickets, reply, and reopen resolved requests. Ticket ownership is checked on every API request.
- **Agent:** can view assigned and unassigned queue items, update permitted tickets, respond, add private internal notes, and use queue search and filters.
- **Administrator:** can view and assign all tickets, manage roles and account status, maintain categories, and view workspace analytics and activity history.

The registration endpoint always creates a customer. Create the first admin through the seed script; administrators can promote customer accounts to agents or admins. API authorization is enforced on the server.

## API

The API uses `/api` as its base. See [docs/API.md](docs/API.md) for routes and response behavior. The health endpoint is `GET /api/health`.

## Authentication and data

JWTs are stored in HTTP-only, same-site cookies rather than browser storage. Mutating requests require a CSRF token returned by `GET /api/auth/csrf`. Passwords are hashed with bcrypt. MongoDB is the source of ticket, user, category, and dashboard data. Internal notes are filtered from customer API responses.

Never commit `.env` or real credentials. `.env.example` contains placeholders only.
